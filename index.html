1. Architecture & Core Features

Quantura™ is a full-stack autonomous trading terminal supporting Binance Spot (1x) and USDT-M Perpetual Futures (1x–50x) across 30 monitored pairs with strict architectural isolation across markets and execution modes.

Strict Market & Execution Mode Isolation

  • Spot vs. USDT-M Futures: Dedicated equations, fee structures, leverage rules (1x Long-only Spot vs. 1x–50x Long/Short Futures), and segregated balance ledgers.
  • Paper · Testnet · Live Separation: Active positions, trade histories, risk scopes, and execution logs remain strictly isolated across PAPER, BINANCE_TESTNET, and BINANCE_LIVE.
  • 30 Monitored Market Pairs: Real-time WebSocket tickers (binanceWebSocket.ts) + live User Data Stream fills (binanceUserStream.ts) paired with cached multi-timeframe REST klines, order-book imbalance, and futures derivatives telemetry.

5 Institutional Execution, Quant Validation & Persistence Phases

  • Phase 1 — Differential Sync & Relational Trade DB: robustSyncEngine.ts compares structural position signatures (ignoring pure mark-to-market noise) to reduce DB overhead, paired with PostgreSQL relational persistence (tradeDb.ts + Prisma) and WAL recovery.
  • Phase 2 — Live Exchange Sync & Idempotent Manager: binanceWebSocket.ts + binanceUserStream.ts + liveOrderManager.ts enforce deterministic clientOrderId idempotency and instant order/fill sync.
  • Phase 3 — Smart Order Router & TCA: smartOrderRouter.ts optimizes maker/limit/market routing with live Transaction Cost Analysis (TCA).
  • Phase 4 — Institutional Flow, Correlation & Blackout Guard: Scores institutional order flow (institutionalFlow.ts), caps correlated clusters (RollingCorrelation.ts), and blocks entries during macro news blackouts (EventBlackoutGuard.ts).
  • Phase 5 — Monte Carlo, Walk-Forward, Multi-Venue Hedge & CORTEX AI: Validates strategies statistically out-of-sample, monitors cross-venue hedges (multiVenueHedging.ts), and pairs econometric ROC-AUC / Half-Kelly scoring with the post-trade Autopsy Room.

2. 12 Specialized Strategies, 1R Profit Protection & Risk Engine

Unrestricted Strategy Selection (0–12) & Specialized Scanning

  • 12 Quantitative Strategies: LIQUIDITY_HUNT (15m), MTF_CONFLUENCE (15m), MEAN_REVERSION (15m), SCALPER (15m), VWAP_VOLUME_DELTA (30m), BREAKOUT (30m), SESSION_ORB_BREAKOUT (30m), INSTITUTIONAL_SMC (1h), MOMENTUM_TREND_PRO (1h), FUNDING_SQUEEZE (1h), ORDER_BLOCK_DISPLACEMENT (1h), and SWING (4h).
  • Full User Freedom (0–12): Arm 1, 2, 3, or all 12 strategies freely with zero forced minimum strategy locks.
  • Per-Strategy Specialized Scanning (AUTO Mode): Each active strategy evaluates symbols on its own specialized timeframe, and valid candidates are ranked by Confidence and Risk/Reward.

Liquidity Sweep Entries & 1R-Aligned Profit Protection

  • Stop-Hunt Sweep & Anti-Chase Gate: Detects 3-candle liquidity sweeps with wick-rejection & reclaim confirmation while blocking extended entries beyond 1.45× ATR from EMA20 (1.60× Breakout, 1.85× confirmed sweep reclaim).
  • Bounded Structural Stop Loss: Tight post-sweep structural SL (1.25×–2.35× ATR, up to 2.8× ATR Swing, min 0.8%–0.9%) paired with TP1 ≥ 2.05× Risk.
  • 1.0R Trailing & 35% Early Secure: RoeEngine waits for >= 1.0R and >= 6.0% Net ROE before arming ATR_DYNAMIC trailing; Early Secure locks 35% + fee-aware breakeven at >= 1.15R (>= 5.0% Futures / >= 1.5% Spot Net ROE).
  • Risk Engine Scaling: Enforces R:R >= 1:2.0, correlation cluster limits, daily loss circuit breakers, and dynamic strategy risk budgets that scale cleanly for 1–2 strategy setups.

5. System Prerequisites

  • OS: Debian 12 (Bookworm) or Ubuntu 22.04 / 24.04 LTS
  • Compute: 2+ vCPUs, 2+ GB RAM, 15 GB SSD
  • Runtime & DB: Node.js v20+ (v22 LTS recommended) & PostgreSQL 16+
  • Ports: 22 (SSH), 80 (HTTP), 443 (HTTPS)

7. Nginx WebSocket Reverse Proxy & SSL

server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}
sudo ln -s /etc/nginx/sites-available/quantura /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d your-domain.com
sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw enable

8. Connecting Binance API (Spot / Futures · Testnet / Live)

  1. Generate API keys from Binance Mainnet or Testnet (testnet.binance.vision / testnet.binancefuture.com).
  2. Enable only Spot & Margin Trading and/or Futures. Keep Withdrawals disabled.
  3. Open Quantura's Binance API Setup Modal, copy your outbound VPS IP address, and whitelist it inside Binance API IP restrictions.
  4. Select the exact Market (SPOT or FUTURES) and Network (Testnet or Live), paste keys, verify connection, and save.

9. Private Server Access & Smart Adaptive 2FA

Private Single-Owner Policy: Public sign-up is permanently blocked on the login screen and at /api/auth/register. Failed login or 2FA verification attempts trigger progressive cooldown lockouts automatically.
  1. Sign in immediately via the zero-lag Owner Sign In console using your configured owner credentials.
  2. If using an initial bootstrap password, rotate it immediately and scan the QR code with Google Authenticator or Authy to issue your 8 salted one-time emergency recovery codes (QNT-XXXX-XXXX).
  3. At login verification, use the auto-submitting 6-box OTP input (Authenticator TOTP or 6-digit Master PIN) or a one-time recovery code, and optionally trust your workstation for 30 days.
  4. Manage Strict 2FA Always (zero device bypass), active Trusted Devices revocation, Recovery Code regeneration, and Master PIN hashing anytime inside Settings → Security & 2FA.

10. Ed25519 License Server Integration & Protected Builds

License-Only Commercial Distribution & Signature Verification

  • Asymmetric Ed25519 Signing (npm run license:keygen): Generates keys/license_private.pem (kept strictly on your License Server to sign POST /api/v1/license/verify payloads) and keys/license_public.pem (for client verification).
  • Protected Release Package (npm run build:dist-protected): Builds Vite frontend, compiles server.ts with DEFAULT_ACTIVE_LICENSE stripped at compile time, obfuscates dist/server.cjs, embeds the Ed25519 public key, and emits a clean source-free package inside release-protected/.
  • Strict Signature Mode (--strict-signature): Pass -- --strict-signature or set STRICT_LICENSE_SIGNATURE=true once your License Server attaches signed Ed25519 envelopes to reject unsigned or spoofed responses.
  • Hardware Sealing & Denial Enforcement: Seals .quantura_certificate.json to the host HWID with a 72-hour outage grace window while rejecting tampered certificates and explicit server denials immediately.
