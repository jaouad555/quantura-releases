1. مميزات البوت والقدرات المؤسسية

تُعد منصة كوانتورا (Quantura™) نظام تداول كمي وخوارزمي مؤسسي متكامل يعمل بشكل آلي 24/7 على أسواق Binance Spot (1x) و Binance USDT-M Futures (1x–50x) عبر 30 زوج تداول مع عزل تام بين أوضاع Paper و Testnet و Live:

12 استراتيجية كمية متخصصة + حرية الاختيار الكاملة (0–12)

يمتلك البوت 12 استراتيجية كمية متخصصة مع حرية كاملة في تفعيل من 0 إلى 12 استراتيجية، وبوضع AUTO يفحص الماسح كل استراتيجية على إطارها الزمني المخصص مع فلتر مصائد السيولة ومنع المطاردة السعرية:

  • فريم 15m (4 استراتيجيات): LIQUIDITY_HUNT (مصائد السيولة)، MTF_CONFLUENCE (توافق الفريمات)، MEAN_REVERSION (الارتداد للمتوسط)، وSCALPER (سكالبينج دقيق).
  • فريم 30m (3 استراتيجيات): VWAP_VOLUME_DELTA (ارتدادات VWAP + اختلال الدفتر)، BREAKOUT (اختراقات البولنجر)، وSESSION_ORB_BREAKOUT (اختراق النطاق المؤسسي).
  • فريم 1h (4 استراتيجيات): INSTITUTIONAL_SMC (كتل الأوامر والفجوات)، MOMENTUM_TREND_PRO (الزخم والاتجاه المؤسسي)، FUNDING_SQUEEZE (ضغط التمويل)، وORDER_BLOCK_DISPLACEMENT (كتل الأوامر والانزياح السعري).
  • فريم 4h (استراتيجية واحدة): SWING (صفقات السوينغ متوسطة المدى).

3. المراحل الخمس للتنفيذ المؤسسي والذكاء الاصطناعي

المراحل الخمس لتأمين التنفيذ وتحليل المخاطر

  • المرحلة 1 — المزامنة التفاضلية و PostgreSQL: محرك robustSyncEngine يقارن التوقيع البنيوي للصفقات (تجاهل ضجيج تقلبات الأسعار اللحظية) لتقليل الضغط على قاعدة البيانات مع حفظ علائقي في PostgreSQL (tradeDb) و Prisma.
  • المرحلة 2 — البث الحي وإدارة الأوامر الحتمية: تدفق Binance WebSocket وبث المستخدم اللحظي (binanceUserStream) مع liveOrderManager لمنع تكرار الأوامر (Idempotency).
  • المرحلة 3 — التوجيه الذكي للأوامر (SOR & TCA): محرك smartOrderRouter لتقليل الانزلاق والعمولات وتحليل تكلفة التنفيذ.
  • المرحلة 4 — التدفق المؤسسي والارتباط والأحداث: رصد التدفقات المؤسسية (institutionalFlow)، حدود الارتباط المتحرك (RollingCorrelation)، ودرع التوقف وقت الأخبار الكبرى (EventBlackoutGuard).
  • المرحلة 5 — التحقق الإحصائي والتحوط: اختبارات Monte Carlo و Walk-Forward في الباك-تستر، وحدة التحوط متعدد المنصات (multiVenueHedging)، وحماية أرباح متدرجة 1.0R Trailing و 1.15R Early Secure (35%).

الذكاء الاصطناعي الثنائي والنشر المزدوج على تيليجرام

  • Google Gemini + DeepSeek / Qwen: تقارير كمية، مركز CORTEX للـ ROC-AUC / Half-Kelly، وغرفة تشريح الصفقات (Autopsy Room).
  • البوت التفاعلي الخاص + القناة الرسمية: إشعارات وأوامر تحكم كاملة (/status، /positions، /balance، /scanner، /signals، /start_bot، /stop_bot) مع نشر شفاف لنتائج المحاكاة الورقية على القناة.

4. متطلبات السيرفر (VPS Prerequisites)

  • نظام التشغيل: Debian 12 (Bookworm) أو Ubuntu 22.04 / 24.04 LTS.
  • المواصفات الأدنى: 2 vCPU، 2 GB RAM، 15 GB SSD.
  • قاعدة البيانات: PostgreSQL 16+.
  • المنافذ المطلوبة: Port 22 (SSH), Port 80 (HTTP), Port 443 (HTTPS).

5. خطوات التنصيب الكاملة على سيرفر Ubuntu / Debian VPS

الخطوة 1: تحديث الحزم وتثبيت الأدوات الأساسية وقاعدة البيانات

sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget git build-essential ufw unzip nginx certbot python3-certbot-nginx postgresql postgresql-contrib

الخطوة 2: إعداد قاعدة البيانات PostgreSQL

# 1. الدخول إلى بيئة postgres
sudo -u postgres psql

# 2. إنشاء قاعدة البيانات
CREATE DATABASE quantura;

# 3. إنشاء مستخدم مخصص (استبدل 'your_password' بكلمة مرور قوية)
CREATE USER quantura_user WITH ENCRYPTED PASSWORD 'your_password';

# 4. منح الصلاحيات الكاملة
GRANT ALL PRIVILEGES ON DATABASE quantura TO quantura_user;
\c quantura
GRANT ALL ON SCHEMA public TO quantura_user;

# 5. الخروج من psql
\q

الخطوة 3: تثبيت Node.js (الإصدار v22 LTS) و PM2

curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -

6. إعداد السيرفر العكسي Nginx وشهادة الأمان (SSL)

أ) إنشاء ملف التكوين في Nginx:

sudo nano /etc/nginx/sites-available/quantura

ضع التكوين التالي (استبدل your-domain.com بدومينك الحقيقي):

server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        # دعم الـ WebSocket للبث المباشر للشموع
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}

ب) تفعيل الموقع وإصدار شهادة SSL:

sudo ln -s /etc/nginx/sites-available/quantura /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d your-domain.com

ج) تفعيل الجدار الناري (UFW):

sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

7. نظام الخادم الخاص والمصادقة الثنائية الذكية (Smart Adaptive 2FA)

حماية السيرفر الخاص ومنع التسجيل العام:
تفتح صفحة تسجيل الدخول فوراً بدون تأخير وهي مخصصة لمالك السيرفر فقط (تم إلغاء إنشاء الحسابات العامة في الواجهة ومنعه برمجياً بـ 403 على الخادم). كما تطبق المنصة حظراً زمنياً تلقائياً عند تكرار المحاولات الخاطئة وتوقيع الجلسات بـ HMAC-SHA256.

خطوات تفعيل وإدارة Smart 2FA خطوة بخطوة:

  1. الدخول الأول للمالك: افتح رابط منصتك https://your-domain.com وسجّل الدخول بالبيانات المضبوطة في ملف .env. عند استخدام كلمة مرور أولية سيُطلب منك استبدالها فوراً بكلمة قوية.
  2. ربط تطبيق المصادقة (QR + TOTP): امسح رمز QR عبر Google Authenticator أو Authy من نافذة التفعيل التلقائي أو من الإعدادات → الأمان و 2FA، ثم أدخل 6 أرقام لتفعيل التحقق من السيرفر.
  3. حفظ رموز الطوارئ الـ 8 (One-Time Recovery Codes): عند التفعيل يُصدر السيرفر 8 رموز بصيغة QNT-XXXX-XXXX مشفّرة بـ SHA-256 للاستخدام لمرة واحدة في حال فقدان الهاتف.
  4. شاشة التحقق الذكية بـ 6 خانات: عند الدخول تدعم الشاشة اللصق المباشر والإرسال التلقائي عند الرقم السادس، مع التبديل بين رمز التطبيق، أو رمز PIN البديل المكون من 6 أرقام (مشفّر بـ PBKDF2)، أو رمز الطوارئ.
  5. الوثوق التكيفي بالجهاز (30 يوماً) مقابل الوضع الصارم: يمكنك تحديد خيار الوثوق بهذا الجهاز لمدة 30 يوماً أو تفعيل الوضع الصارم الدائم (Strict 2FA) من الإعدادات لفرض التحقق عند كل دخول وسحب ثقة أي جهاز بنقرة واحدة.

8. نظام التراخيص، التوقيع الرقمي Ed25519 والنسخ المحمية

التوزيع المفتوح مع بيع التراخيص + بناء الحزم المحمية

  • التحقق عبر سيرفر التراخيص (LICENSE_SERVER_URL): عند ضبط QUANTURA_COMMERCIAL_BUILD=true (أو استخدام release-protected/) يُلغى أي مفتاح تجريبي افتراضي، ويبدأ التطبيق بحالة UNLICENSED حتى إدخال ترخيص صالح مربوط ببصمة السيرفر (HWID).
  • توليد مفاتيح Ed25519 (npm run license:keygen): ينشئ المفتاح الخاص keys/license_private.pem (يُحفظ حصراً في سيرفر التراخيص لتوقيع الردود) والمفتاح العام keys/license_public.pem للتحقق داخل التطبيق.
  • شهادات محلية مختومة ببصمة الجهاز: يُختم ملف .quantura_certificate.json بـ HWID وفترة سماح أقصاها 72 ساعة عند انقطاع السيرفر مؤقتاً، مع رفض فوري لأي رفض صريح من السيرفر أو تلاعب بالملف.
  • بناء النسخة المشوّشة الخالية من المصدر: نفّذ npm run build:dist-protected (أو أضف -- --strict-signature لرفض أي رد غير موقّع رقمياً) لتوليد مجلد release-protected/ الجاهز للتوزيع المباشر.
